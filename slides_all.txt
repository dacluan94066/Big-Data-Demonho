Quy Trình Đọc Dữ Liệu (Read Pipeline)
1
open()
Client gửi yêu cầu đọc file tới NameNode.
2
Tra cứu

3

VÍ DỤ
File report.csv có Block A ở Node 1 và Block B ở Node 4. Client hỏi NameNode đúng một lần, sau đó tự kéo byte từ Node 1 rồi đến Node 4 — NameNode không bị nghẽn cổ chai (bottleneck).

Quy trình vận hành
Quy Trình Ghi Dữ Liệu Theo Đường Ống (Write Pipeline)
Client tạo file mới → NameNode cấp danh sách 3 DataNode (A, B, C) → dữ liệu chia thành gói tin (Packets ~64 KB) và truyền theo đường ống:
Client
Node A
Node B
Node C
Ack (xác nhận) →  ngược lại  C → B → A → Client cho từng gói tin
1
Client yêu cầu NameNode tạo file mới; NameNode kiểm tra quyền và cấp quyền ghi.
2
NameNode cấp danh sách 3 DataNode để lưu trữ (VD: Node A, B, C).
3
Client chia nhỏ block thành các gói tin (Packets, cỡ ~64 KB).
4
Đường ống: Client → A → B → C, mỗi node ghi rồi chuyển tiếp ngay.

=== SLIDE 14 ===
Cơ chế lưu trữ
Cơ Chế Phân Khối Dữ Liệu (Data Blocks)
HDFS chia nhỏ file lớn thành các khối độc lập (Block). Kích thước mặc định 128 MB — hệ điều hành thông thường chỉ 4 KB. Kích thước lớn giúp giảm số block cần quản lý, tiết kiệm RAM của NameNode và tối ưu tốc độ đọc tuần tự (Disk Seek Time).
VÍ DỤ TRỰC QUAN — FILE LOG 300 MB
file.log — 300 MB
Block 1
128 MB
Block 2
128 MB
Block 3
44 MB
Lưu ý: Block 3 chỉ chiếm đúng 44 MB đĩa thực tế — HDFS không tốn đủ 128 MB cho phần dư.
Lý do chọn kích thước lớn
Giảm số lượng block cần quản lý → tiết kiệm RAM của NameNode và tối ưu tốc độ đọc tuần tự (giảm số lần disk seek).

Kiến trúc
Sơ Đồ Trực Quan — Kiến Trúc Master/Slave
Toàn cảnh một cụm Hadoop: 1 Master Node điều phối nhiều Slave Node. Mỗi Slave vừa lưu trữ dữ liệu (DataNode) vừa tham gia tính toán (Node Manager, Map/Reduce) — đúng theo nguyên lý Data Locality.
SƠ ĐỒ — MASTER NODE & SLAVE NODE
NameNode (Master) quản lý Namespace & vị trí block  →  DataNode (Slave) lưu dữ liệu thô  →  Node Manager/Map-Reduce xử lý tính toán ngay tại đó
